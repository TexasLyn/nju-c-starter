# D · 让 AI 当你的助教

> 这套材料可以配合 AI 助手用，效果比单打独斗好很多——**前提是你要把 AI 用对**。
> 用错了，它会直接把答案给你，你什么都学不到。

---

## 1. 最重要的一条规则

**不要问"这道题怎么做"。**

一问这个，AI 就会噼里啪啦给你一段完整代码。你复制粘贴、运行通过、感觉很爽，然后考试的时候一个字都写不出来。

**要这么问**：

> "我在做 `practice/L05_3.c`，我的思路是 XXXX，写到第 3 步卡住了，编译报错 `XXXX`。
> **请先别给我完整代码**，帮我看看我的思路哪里有问题。"

---

## 2. 现成的提示词（复制粘贴就能用）

本仓库的 `prompts/` 目录里放了几个写好的提示词，按你的场景挑一个：

| 文件 | 什么时候用 |
|---|---|
| [01-助教模式.md](../prompts/01-助教模式.md) | **最常用**。让 AI 当你的 C 语言助教，只引导不给答案 |
| [02-报错解读.md](../prompts/02-报错解读.md) | 编译器报了一堆看不懂的错 |
| [03-代码审查.md](../prompts/03-代码审查.md) | 你写完了、能跑，但想让人挑毛病 |
| [04-自测出题.md](../prompts/04-自测出题.md) | 学完一课，想让人出题考你 |
| [05-环境配置.md](../prompts/05-环境配置.md) | 让能操作你电脑的 AI 直接帮你把环境装好 |

**怎么用**：打开那个文件，把里面的内容**整段复制**，粘到你的 AI 对话框里，然后接着描述你的具体问题。

每个提示词的末尾都留了 `【这里填你的...】` 的占位符，填上再发。

## 3. 三种 AI 的用法不一样

不同工具能力差很多，用法也不同：

### 只有聊天窗口的 AI（网页版 ChatGPT / Claude / 豆包 / DeepSeek）

**能力**：能读你粘贴的代码，能解释概念，能出题。**看不见你的文件**。

**怎么用**：

1. 复制提示词 `prompts/01-助教模式.md`
2. 把你的代码**整段粘贴**进对话框（别截图，AI 读文字更准）
3. 把编译器的报错**也粘贴进去**（同样别截图）

**注意**：每次开新对话，AI 都忘光了之前的事。所以提示词要**每次重新粘贴一遍**。

### 能读你文件的 AI（Cursor / GitHub Copilot / ZCode / Claude Code）

**能力**：能直接读你电脑上的 `practice/L05_3.c`，能跑编译命令看报错，能读 `docs/` 里的讲义。

**怎么用**：

1. 在 `c-starter` 目录里打开这个 AI 工具
2. 粘贴提示词 `prompts/01-助教模式.md`
3. 然后就可以直接说「帮我看看 practice/L05_3.c，我卡在中间那个循环上了」——它自己会去读文件

**优势**：你不需要复制粘贴代码，它也不会瞎猜你的上下文。

### 能改你文件的 AI（ZCode / Claude Code / Cursor 的 Agent 模式）

**能力**：上面全部，外加**能直接跑终端命令、能改代码**。

**怎么用**：这种工具**最适合搭配 [05-环境配置.md](../prompts/05-环境配置.md)**——把提示词改一下系统名，丢给它，它会自己检查环境、装编译器、跑通评测脚本。

⚠️ **用它改你的练习代码前想清楚**：它可以一键把答案写出来。让它改的时候明确说「**只指出问题，不要替我写**」，否则你就是在看答案。

## 4. 好用法 vs 坏用法

| 场景 | ❌ 坏用法 | ✅ 好用法 |
|---|---|---|
| 编译报错 | 「这个错什么意思，帮我改」 | 「报错 `expected ';' after expression`，我看了第 23 行没觉得有问题，你帮我看看**是不是报错行号指错了地方**」 |
| 想不出思路 | 「这题怎么做」 | 「这题要统计出现次数最多的字符，我能想到两层循环但觉得太慢，**有没有更简单的方法，先只给思路**」 |
| 代码能跑但感觉写得烂 | 「帮我优化」 | 「这段能跑通，但我用了 3 个嵌套循环，**帮我看看有没有冗余的判断**」 |
| 学完一课 | 「再给我讲一遍」 | 「出 5 道题考我第 10 课的内容，**先只给题目，我做完你再批改**」 |
| 概念不懂 | 「指针是什么」 | 「我理解 `int *p = &x` 是把 x 的地址存进 p，但**为什么 `*p = 10` 能改 x，而 `p = 10` 不行**？」 |

**看规律**：好用法都包含三个要素——**你的具体尝试、你卡在哪、你要 AI 做什么**。

---

## 5. 怎么判断 AI 在胡说

AI 讲 C 语言**大部分时候是对的，但会编**。下面这些情况要警惕：

| 情况 | 怎么办 |
|---|---|
| AI 给的代码你**编译不过** | 把它贴回去：「这段编译报错 XXXX，你确认一下」——通常它第二次就对了 |
| AI 提到某个函数你**在讲义里没见过** | 搜一下这个函数的头文件，或者直接问「这个函数在哪个头文件里」 |
| AI 说的和你**教材/讲义冲突** | **以讲义和编译器为准**。C 语言的事实是编译器说了算，AI 可能记错 |
| AI 给的答案**特别长特别复杂** | 本仓库的练习都是基础题，**不该超过 30 行**。太复杂就是它想多了，让它「用最基础的方法重写」 |

🔸 **最终的裁判是编译器，不是 AI。** 任何说法，跑一遍就知道了。

## 6. 一个完整的对话示例

感受一下「好用法」长什么样：

> **你**：（粘贴 `prompts/01-助教模式.md` 全文）
>
> **你**：我在做 `practice/L05_4.c`，题目是输出 100 以内的所有素数。
> 我的想法是对每个数 n，从 2 试到 n-1，只要有一个能整除就不是素数。
> 我写了：
> ```c
> for (int n = 2; n <= 100; n++) {
>     for (int i = 2; i < n; i++) {
>         if (n % i == 0) {
>             printf("%d ", n);
>         }
>     }
> }
> ```
> 输出比答案多了很多数。**别给我完整代码，告诉我逻辑错在哪。**
>
> **AI**：你的内层循环一发现能整除就打印了，但这时候循环还在继续。比如 n=12，i=2 时发现能整除、打印了 12；i=3 时又打印一次。
>
> 两个问题：
> 1. 应该**标记**「它不是素数」，然后在**内层循环结束后**再决定打不打印
> 2. 现在这样 n=12 会被打印好几次，所以"多了很多数"
>
> 想想看：需要一个变量来记「有没有找到过因子」，找出循环外面在哪判断。
>
> **你**：懂了，加个 `int isPrime = 1;`，找到因子就设成 0……
>
> **AI**：对，试试。还有一个可以优化的地方——内层循环真的要试到 `n-1` 吗？

这就是理想状态：**AI 指出方向，你自己动手。**
