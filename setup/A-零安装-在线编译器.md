# A · 零安装：用在线编译器开始学

> **这条路的承诺**：不装任何东西，打开一个网页就能写 C 程序。
> **代价**：用不了本仓库的自动评测脚本，第 14 课（文件读写）做不了。

---

## 1. 打开这个网址

→ **https://www.programiz.com/c-programming/online-compiler/**

（国内如果打不开，备选：https://c.runoob.com/compile/11/ ，或者搜"在线 C 编译器"，很多网站都有。）

你应该看到一个分为两半的页面：**左边是写代码的地方，右边是显示结果的地方**。

---

## 2. 把这段代码全部粘贴到左边

```c
#include <stdio.h>

int main(void)
{
    printf("Hello, C!\n");
    return 0;
}
```

粘贴前先把左边的示例代码**全选删掉**（`Ctrl+A` / `Cmd+A` 然后删）。

---

## 3. 点那个绿色的运行按钮

右边应该出现：

```
Hello, C!
```

**恭喜，你已经跑通第一个 C 程序了。**

---

## 4. 现在做真正的第一道练习

左边删掉，换成这个：

```c
#include <stdio.h>

int main(void)
{
    printf("第一行\n");
    printf("第二行\n");
    return 0;
}
```

运行，看看是不是两行。

然后把第一个 `\n` 删掉，再运行，看看变成什么样了：

```c
    printf("第一行");
    printf("第二行\n");
```

输出会变成 `第一行第二行`（挤在一行）。

**这就是 `printf` 最容易搞错的地方**：它不会自动换行，想要换行必须自己写 `\n`。

---

## 5. 怎么学下去

在线编译器只是你的"运行按钮"。教材部分照常读：

1. 打开本地（或平板上的）`docs/01-第一个C程序.md`
2. 讲义里的每段示例代码，都**粘贴到在线编译器里跑一遍**——光看是不会的
3. 读到「本课练习」，把 `practice/L01_1.c` 里的题目注释复制出来，在在线编译器里写

### 题目在哪

`practice/` 目录里每个 `.c` 文件的开头都写着：

```c
/*
 * L01_1 · 用 printf 打印图案
 *
 * 【题目】
 *   打印如下图形：
 *      *
 *     ***
 *    *****
 *
 * 【输出格式】
 *   四行，注意每行前面的空格也要一模一样。
 *
 * 【提示】
 *   ...
 */
```

把 `【题目】` 那段读懂，就在在线编译器里写。

### 怎么知道写对了

没有自动脚本，就用**肉眼比对**。本仓库给每道题准备了标准答案的期望输出：

- `tests/cases/L01_1.out` —— 这是**期望输出**（程序应该打印什么）
- `answers/L01_1.c` —— 这是**参考代码**（**卡住了再看，别一开始就抄**）

在平板上读这两个文件，或者在电脑上用文本编辑器打开，对着比。

🔸 **一个土办法**：写完后把「空格」都数清楚。C 的图形题最常见的错误就是少一个空格，而这类错误在屏幕上几乎看不出来。

## 6. 什么时候该去装真正的环境

出现下面任何一条，就该走 [B](B-Windows本机安装.md) / [C](C-macOS本机安装.md) 线了：

- 你做完第 13 课了（**第 14 课是文件读写，在线编译器做不了**）
- 你觉得每次复制粘贴太烦
- 你想用 `python3 tests/check.py` 自动判题（省下大量肉眼比对的时间）

**不用着急。** 前 13 课用在线编译器完全够，学完再装环境完全来得及。

## 附：在线编译器上几个常见的坑

**① 输出窗口一闪就没了**

如果程序没输出，先看是不是**编译失败**了。在线编译器通常会在输出区显示红色报错，格式类似：

```
error: expected ';' after expression
```

**② 中文变成乱码**

有些在线编译器的输出窗口编码不对。解决：把 `printf` 里的中文换成英文试试，能正常显示就是编码问题，不影响你学语法。

**③ 看到 `Time limit exceeded` 或程序卡住**

这就是死循环，检查你循环的退出条件。点"停止"按钮重来。

**④ 想输入数据怎么办**

本仓库第 3 课以后很多题要读输入（`scanf`）。在线编译器的输入框通常在页面下方或右侧，标着 **Input** 或 **标准输入**，把测试数据粘进去再点运行。

`tests/cases/L01_2.in` 这类文件就是给你粘贴的输入数据。
