# 01 · 第一个 C 程序

> **本课内容：编译上手 + printf 输出 + 调试**
> 这一课先搞懂一件最重要的事：**编译**——你写的代码为什么不能直接运行。然后学会用 `printf` 把东西精确地打到屏幕上。

---

## 1. 写代码这件事，比你想的多两步

你可能会觉得：写程序就是"把想法打成代码，然后运行"。

对 C 来说不是。中间还隔着**一步关键的工序**。

### 先说个你熟悉的场景

你在手机上发一条消息，对方收到的是文字。但这条消息在网络上传输的时候，是一串电信号。**中间有个东西帮你把文字翻译成了信号**，你不需要知道这个翻译过程。

写 C 程序也是类似的道理，只不过这次翻译的对象是代码：

```
   你写的 hello.c          →    [ 编译器 ]    →      hello        →   运行
   （人能看懂）                                    （CPU 能看懂）      （出结果）
     源代码                                         可执行文件
```

### 三个名词，先认识一下

| 名词 | 是什么 | 举例 |
|---|---|---|
| **源代码**（source code） | 你写的那堆文字，给人看的 | `hello.c` |
| **编译器**（compiler） | 一个程序，负责把源代码翻译成机器能执行的格式 | `clang`、`gcc` |
| **可执行文件**（executable） | 翻译出来的成品，CPU 直接能跑 | `hello.exe`、`hello` |

**关键点：你写的源代码，CPU 是看不懂的。** 必须先翻译。

这也是为什么你不能像双击打开一个文档那样"运行"一个 `.c` 文件——它不是成品，它是原料。

### 这个链条决定了 C 的报错分两种

记住上面那张图，因为 C 的报错分成两大类，看现象就能分清：

| 现象 | 叫什么 | 意思 |
|---|---|---|
| 屏幕上一堆 `error`，程序压根没跑起来 | **编译错误** | 翻译没成功，语法写错了 |
| 编译过去了，程序也跑了，但结果不对 | **逻辑错误** | 翻译成功了，但你的意思表达错了 |

**第二种更麻烦**，因为它没有任何报错信号。程序安安静静地给你一个错误的答案，你还以为是对的。

这也是为什么后面每一课都会专门讲「新手最常犯的错」——那些错基本都是第二类。

### 顺便记住一件事

编译这件事**不是一次性的**。你每次改了代码，都要重新编译一遍，因为改了源代码，之前的成品就过期了。

🔸 所以在编辑器里点"运行"的时候，它其实偷偷做了两件事：先编译，再运行。理解了这一点，你就知道为什么改了代码不重新编译会"没生效"。

## 2. 最短的 C 程序

```c
#include <stdio.h>

int main(void)
{
    printf("你好，C 语言！\n");
    return 0;
}
```

逐行拆开看，暂时不用全懂，先建立印象：

**`#include <stdio.h>`**

`include` 是"包含"的意思，`stdio` 是 **st**andard **i**nput **o**utput（标准输入输出）的缩写。这一行等于在说：

> "下面我要用到的输入输出功能（比如 `printf`），去 `stdio.h` 这个文件里找。"

🔸 **这里先记住写法就行**：**只要你的程序要打印东西或者读键盘输入，第一行就写它。**漏了它会怎样？`printf` 会被当成一个不认识的名字，直接编译报错。这是新手第一大坑。

注意这一行**末尾没有分号**。`#` 开头的叫**预处理指令**，是给编译器看的命令，不是 C 语句。

**`int main(void)`**

`main` 是主函数，**每个 C 程序有且只有一个**。程序运行的第一件事，就是执行 `main` 里面的内容。

`int` 和 `(void)` 现在还不用深究，🔸 **先记住：程序的骨架就这么写**。第 7 课讲函数时会回来解释它为什么长这样。

🔸 **这一点很重要**：C 程序不是「从第一行开始跑」的，而是**从 `main` 开始跑**。写在 `main` 外面的代码不会自己执行。所以一个程序里可以有很多函数，但只有 `main` 是入口。

**`{` 和 `}`**

大括号圈起来的部分叫**函数体**，就是"这个函数要干什么"。

**大括号的作用是划分范围**：哪几句话属于这个函数，哪几句不属于。

⚠️ 提醒：C 里缩进**只是给人类看的**，编译器完全不在乎你把代码缩进成什么样。这不是说可以不缩进——不缩进的代码你自己三天后就看不懂了。CLion 会自动帮你缩进，不用手动调。

**`printf("你好，C 语言！\n");`**

打印一行字。注意三件事：

1. **末尾必须有分号 `;`**。C 的每一条语句末尾都要有分号，漏了是最常见的编译错误，没有之一。
2. `\n` 是**换行符**，一个字符，不是两个。后面单独讲。
3. 引号是**英文双引号**。中文引号 `“”` 会让编译器报一堆莫名其妙的错。

**`return 0;`**

`main` 函数结束时返回一个数字给操作系统。🔸 **先记住：每个程序结尾都写 `return 0;`，0 的意思是"正常结束"。**

## 3. 动手改一改：亲眼看看报错长什么样

光读代码记不牢。这一节请你**真的动手**：先把程序跑通，然后**故意改坏它**，看会报什么错。

🔸 **「故意写错、观察报错」是学编程最快的办法。** 后面每一课遇到新语法，都可以这么做。

### 第一步：先跑通

打开 `practice/L01_1.c`，或者新建一个文件，输入：

```c
#include <stdio.h>

int main(void)
{
    printf("第一行\n");
    printf("第二行\n");
    return 0;
}
```

运行，你应该看到两行输出。

### 试一试 ①：故意漏掉分号

把第一句 `printf` 末尾的分号删掉：

```c
    printf("第一行\n")      /* 这里故意删了分号 */
    printf("第二行\n");
```

再运行。你会看到类似这样的报错：

```
error: expected ';' after expression
```

**这就是「编译错误」的样子。** 注意两点：

1. 报错里写着 `expected ';'` —— 它在说「这里应该有分号」
2. 报错的行号可能指向**下一行** —— 所以看到莫名其妙的报错，先往上看一行

把分号加回去，程序又能跑了。**你已经完成了一次「调试」。**

### 试一试 ②：故意删掉换行符

把两个 `\n` 都删掉：

```c
    printf("第一行");
    printf("第二行");
```

运行，输出会变成：

```
第一行第二行
```

**这就是 `printf` 和很多人直觉不一样的地方：它不会自动换行**，想要换行必须自己写 `\n`。

### 试一试 ③：故意用中文标点

把某一句末尾的英文分号换成中文分号 `；`：

```c
    printf("第一行\n")；      /* 中文分号 */
```

报错信息里会出现 `non-ASCII characters`。

🔸 **记住这个短语**，以后看到它就知道是「中文标点混进代码里了」。这是中文用户最常见的问题，因为中英文标点在屏幕上几乎长得一样。

### 试一试 ④：故意漏掉 `#include`

把第一行 `#include <stdio.h>` 删掉，再运行。报错里会有：

```
call to undeclared library function 'printf'
```

意思是「我不认识 `printf` 这个东西」。因为 `printf` 的定义在 `stdio.h` 里，你把它删了就找不到了。

**报错里出现 `undeclared function`，第一反应就是「是不是漏了某个 `#include`」。**

## 4. 转义字符：字符串里的"特殊写法"

在字符串里，有些字符没法直接写。比如你要打印一个双引号 `"`，直接写就会和字符串的引号打架：

```c
printf("他说："你好"");   // ✗ 编译器懵了，它分不清哪对引号是一对
```

解决办法是用**反斜杠 `\`** 开头，表示"接下来这个字符有特殊含义"。这叫**转义字符**。

| 写法 | 含义 | 什么时候用 |
|---|---|---|
| `\n` | 换行 | 最常用，几乎每句 printf 都带 |
| `\t` | 制表符（一个大的对齐空格） | 输出表格、对齐 |
| `\\` | 一个反斜杠 | 要打印 Windows 路径 `C:\Users` |
| `\"` | 一个双引号 | 字符串里要包含引号 |
| `%%` | 一个百分号 | 注意！**百分号不是 `\%`，是 `%%`** |

举几个例子：

```c
printf("第一行\n第二行\n");     // 输出两行
printf("姓名\t年龄\n");         // 用制表符对齐
printf("路径：C:\\Users\\texas\n");  // 输出 路径：C:\Users\texas
```

⚠️ 最常见的一个坑：**要打印一个反斜杠，得写两个。** `\U` 在 C 里没有特殊含义，编译器会警告你 `unknown escape sequence`。写 `\\` 才对。

## 5. 怎么跑起来

**方式一：用评测脚本（推荐，最省事）**

```bash
cd c-starter
python3 tests/check.py L01_1 --dir practice
```

它会自动编译、喂输入、和标准答案比对，然后告诉你哪一行不一样。**这就是在线判题系统（OJ）的手感。**

**方式二：手动编译运行**

```bash
# macOS / Linux
clang -std=c11 -Wall -Wextra -g practice/L01_1.c -o /tmp/a && /tmp/a

# Windows PowerShell（注意 python 不带 3、路径用反斜杠）
gcc -std=c11 -Wall -Wextra -g practice\L01_1.c -o a.exe; .\a.exe
```

⚠️ **`-Wall -Wextra` 一定要加**，它们会打开所有警告，很多 bug 靠警告才能发现。

**方式三：用 CLion（有的话最舒服）**

1. 用 CLion 打开这个目录
2. 打开 `practice/L01_1.c`，把标了 `TODO` 的地方填上
3. 右上角下拉框选 `L01_1`，点绿色三角 ▶

CLion 会自动编译再运行，结果显示在下面的窗口里。

**如果程序要你输入**（比如后面那些 `scanf` 的题），在运行窗口里直接敲数字，按回车。

**如果报错了怎么办？** 先看 [99-报错速查](99-报错速查.md)，里面把最常见的报错信息都翻译成中文了。翻两次你就能自己看懂了。

## 6. 本课最少必要记忆

1. **骨架固定**：`#include <stdio.h>` → `int main(void) { ... }` → `return 0;`
2. **每句话末尾都要有分号 `;`**（`#include` 那行除外）
3. `printf` **不会自动换行**，想换行自己写 `\n`
4. 要打印反斜杠写 `\\`，要打印百分号写 `%%`
5. 报错分两种：**编译错误**（压根没跑起来，语法问题）和**逻辑错误**（跑起来了但结果不对）

## 7. 新手最常犯的 3 个错

**① 漏分号**

```c
printf("你好\n")     // ✗ 报错：expected ';' after expression
printf("你好\n");    // ✓
```

报错信息里提到 `expected ';'` 或者行号指在下一行，八成就是上一行漏了分号。

**② 用了中文标点**

```c
printf（"你好"）；   // ✗ 括号和分号是中文全角的
printf("你好");      // ✓
```

这个错误很难用眼睛看出来，因为中英文标点在屏幕上长得像。报错信息通常是 `non-ASCII characters are not allowed outside of literals and identifiers`——**看到 non-ASCII 这三个字，第一反应就是去找中文标点。**

如果你用中文输入法，写完标点后记得切回英文。CLion 不会自动帮你改这个。

**③ 忘了 `\n`，所有输出挤成一行**

```c
printf("第一行");
printf("第二行");
```

输出是 `第一行第二行`，不是两行。
