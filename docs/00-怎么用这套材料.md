# 00 · 怎么用这套材料

## 一句话

这是一套**自学用**的 C 语言教材 + 题库 + 可以跑的工程。对着你真实的一门大学 C 语言课程 14 课的内容编写，学完一课就能上手做题。

## 目录里都有什么

```
c-starter/
├── README.md          总入口，看进度
├── docs/              讲义，从 01 到 15，还有一份报错速查
├── practice/          练习骨架 ← 你在这里写代码
├── answers/           参考答案 ← 卡住了再看

    └── cases/         每道题的输入和期望输出
```

## 每次学一课，按这个顺序做

**第一步：读讲义**（`docs/01-第一个C程序.md` 这样按序号读）

30～40 分钟能读完一课。读完不用回头背，讲义最后一节「最少必要记忆」就是需要记住的东西。

**第二步：打开 `practice/L01_1.c`，把 `TODO` 填掉**

每道题的骨架里都写好了：

- 题目在文件最上面的注释里
- 输入输出格式也写在注释里
- 需要你写的地方标了 `TODO`
- 骨架**一定能编译通过**，所以你写完点运行，不会突然冒出一堆看不懂的编译错误

**第三步：运行**

在 `c-starter` 目录下执行（Windows 上把 `python3` 换成 `python`、斜杠换成 `\`）：

```bash
python3 tests/check.py L01_1 --dir practice
```

它会编译你的代码、自动喂输入、和标准答案比对，然后告诉你哪一行不一样。**这就是在线判题系统（OJ）的手感**，很多上机练习也是这个形态。

**想手动跑也行**：

```bash
# macOS / Linux
clang -std=c11 -Wall -Wextra -g practice/L01_1.c -o /tmp/a && /tmp/a

# Windows PowerShell
gcc -std=c11 -Wall -Wextra -g practice\L01_1.c -o a.exe; .\a.exe
```

**程序要你输入的时候**，就在终端里直接敲数字，按回车。

**用 CLion 的话更省事**：右上角下拉框选 `L01_1`，点绿色三角，程序要输入时在下面的运行窗口里敲。

**第四步：看输出对不对**

如果拿不准，回到第三步的评测脚本——它就是干这个的。手动跑的话，对着 `tests/cases/L01_1.out`（期望输出）比一眼。

**第五步：实在卡住了再看 `answers/L01_1.c`**

顺序很重要：先自己写，写不出来再抄。抄完要能合上答案自己重写一遍，不然等于没学。

## 关于「看不懂」这件事

先说清楚：**C 语言里有一大半概念，第一遍看就是会不懂，这是正常的，不是你笨。**

原因是 C 的设计是一层套一层的，后面的概念需要前面的概念做地基。「地址」「指针」这种东西，第 1 课讲不清楚，因为你还不知道变量在内存里长什么样。

所以这套讲义里的每一课都会明确告诉你：

> 🔸 **这里先记住写法就行，第 8 课会回来解释为什么。**

看到这种标记，你就**照抄写法，继续往下走**。别停在那儿死磕，那是效率最低的学法。

反过来说，遇到以下情况请务必停下来想清楚，因为这些是"地基"：

- 讲义里标了 **关键** 的地方
- 讲义最后「最少必要记忆」里列的东西
- 「新手最常犯的错」里提到的

## 卡住的时候怎么办

**第一，先看 `docs/99-报错速查.md`。**

C 的编译错误一开始看着像天书，但其实来回就那十几种。速查表里把最常见的那些错误信息、中文翻译、怎么改，都列出来了。翻两次你就会发现报错其实挺好懂的。

**第二，分清是哪种错。**

| 现象 | 意思 | 去哪儿看 |
|---|---|---|
| 编译报错，程序根本没跑起来 | 语法写错了，比如少分号、少括号 | 速查表前半部分 |
| 编译过了，但程序行为不对 | 逻辑错了，得靠调试 | 速查表后半部分 |
| 程序跑起来就不动了 | 死循环，循环条件写错了 | 速查表「死循环」那一节 |
| 输出一堆奇怪的数字或乱码 | 变量没初始化，或者类型不匹配 | 速查表「垃圾值」那一节 |

**第三，用 printf 调试。**

这是最土但最有效的办法。程序行为不对的时候，在怀疑的地方插一句：

```c
printf("到这里了，x = %d\n", x);
```

跑一遍，看看到底走到哪一步、变量的值是多少。**这个笨办法能解决你遇到的八成问题**，别嫌土。

## 关于教材写法和本机写法的差异（重要）

你的教材和配套答案里用的是这样几样东西：

```c
#include <conio.h>    // Turbo C 时代的头文件
clrscr();             // 清屏
gets(str);            // 读一行字符串
```

**这些东西在 macOS 上全都用不了。** `conio.h` 这个头文件在 macOS 上根本不存在，`gets` 因为太危险已经被 C 语言标准删掉了。

所以：

- **自己在本机练习** → 用讲义里给的现代写法（我会在用到的地方给出替换方案）
- **要按教材写法提交的练习** → 按教材的写法写，因为有些老环境只支持教材写法

两套写法讲义里都会给，不会让你为难。

## 学习节奏建议

你的目标是「快速突击，先把基础全过一遍」。按这个节奏：

- **一天一课**，14 天过完基础部分，每天 1.5～2 小时
- 不要跳过练习。读讲义只能让你"看懂了"，写练习才能让你"会写了"，这两件事之间隔着一条鸿沟
- 每课的题不用全做对才能往下走。**能做对大部分就可以前进**，剩下一两题标记一下，以后回头看

## 平板场景

如果你在平板上，没有电脑：

- `docs/` 里全是纯文本 Markdown，任何笔记软件都能读
- 讲义里的题都在纯文本里，可以当纸面练习，拿笔写代码
- 讲义里的程序阅读题（给你一段代码，问输出是什么）**特别适合在纸上做**，这正是上机题的形式

## 最后一句

C 语言不难，它只是**不替你擦屁股**。别的高级语言里你写错一个类型，它帮你在运行时兜住；C 里同样的错误会安静地给你一个莫名其妙的数字。

这套材料要做的事，就是提前告诉你哪些地方会踩坑。踩坑之前知道有坑，就不慌了。
