# 99 · 报错速查手册

> **用法**：Ctrl+F 搜报错信息里的关键词（英文部分），找到对应的中文解释和改法。
> 前 30 条是编译错误，后面是运行时的怪现象。

---

## 目录

**A. 最常见（先看这五条）**
1. `expected ';'` —— 漏分号
2. `use of undeclared identifier` —— 变量名写错或作用域外
3. `non-ASCII characters` —— 用了中文标点
4. `call to undeclared function` —— 漏了 `#include`
5. `array type ... is not assignable` —— 数组不能整体赋值

# A. 最常见（先看这五条）

## 1. `expected ';' after expression` / `expected ';' at end of ...`

**意思**：这里应该有个分号。

**看哪里**：**报错指向的那一行，或者它的上一行。**

```c
printf("hello\n")        /* ← 报错会指在这里或其下一行 */
printf("world\n");
```

**最常见的两种**：

```c
/* ① 漏了句末分号 */
int a = 5                /* ✗ */
int a = 5;               /* ✓ */

/* ② 结构体定义末尾漏分号（第 13 课重点） */
struct Student {
    int id;
}                        /* ✗ 这里要有分号 */
struct Student { int id; };   /* ✓ */
```

⚠️ **如果报错指向的地方看起来完全没问题，一定要往上看一行。**

---

## 2. `use of undeclared identifier 'xxx'` / `'xxx' undeclared`

**意思**：不认识 `xxx` 这个名字。

**三种可能**：

```c
/* ① 变量名打错了 */
int count = 0;
printf("%d\n", cuont);        /* ✗ 拼错了 */

/* ② 变量定义在别的花括号里，出了作用域就没了（第 8 课） */
if (a > 0) {
    int b = 5;
}
printf("%d\n", b);            /* ✗ b 已经不存在了 */

/* ③ 变量声明在使用之后 */
printf("%d\n", x);            /* ✗ 还没声明 */
int x = 5;
```

**改法**：检查拼写；检查是不是在 `{}` 外面用了里面的变量；把声明挪到使用之前。

---

## 3. `non-ASCII characters are not allowed outside of literals and identifiers`

**意思**：出现了非 ASCII 字符（**你用了中文标点**）。

**✅ 看到 `non-ASCII` 这三个字，第一反应就是去找中文标点。**

```c
printf（"hello"）;        /* ✗ 括号和分号是中文全角 */
printf("hello");          /* ✓ */
if (a ＞ 0) { }           /* ✗ ＞ 是中文全角大于号 */
if (a > 0) { }            /* ✓ */
```

**中英文标点在屏幕上长得几乎一样**，肉眼很难发现。检查方法：

- CLion 里把光标移到报错那行，逐字符左右移动，看标点占的宽度
- 或者让编辑器显示不可见字符

**预防**：写完标点立刻切回英文输入法。中文注释和字符串里的中文是**没问题的**（那些在引号或注释里），报错只针对代码部分的标点。

---

## 4. `call to undeclared function 'xxx'` / `call to undeclared library function`

**意思**：调用了一个没声明的函数。

**两种原因**：

```c
/* ① 漏了 #include */
sqrt(16.0);                  /* ✗ 没 #include <math.h> */
strcmp(a, b);                /* ✗ 没 #include <string.h> */
malloc(100);                 /* ✗ 没 #include <stdlib.h> */
printf("hi\n");              /* ✗ 没 #include <stdio.h> */

/* ② 自己写的函数定义在调用之后，且没有声明（第 7 课） */
int main(void) {
    add(1, 2);               /* ✗ add 还没出现 */
}
int add(int a, int b) { return a + b; }
```

**改法**：

| 用到的函数 | 需要的头文件 |
|---|---|
| `printf` `scanf` `fopen` `fprintf` `fgets` | `<stdio.h>` |
| `sqrt` `fabs` `sin` `cos` `exp` `pow` `log` | `<math.h>` |
| `strlen` `strcpy` `strcmp` `strcat` `strstr` `strncmp` | `<string.h>` |
| `malloc` `free` `abs` `exit` | `<stdlib.h>` |

自己写的函数：把定义挪到 `main` 前面，或者在前面的写一行**函数声明**（`int add(int a, int b);`）。

⚠️ **macOS 的编译器把这一条当硬错误**（老编译器只给警告）。所以漏 `#include` 会直接编译失败。

---

## 5. `array type 'int[5]' is not assignable`

**意思**：数组不能整体赋值。

```c
int a[3] = {1,2,3};
int b[3];
b = a;                       /* ✗ 数组名是地址，不是变量 */

char s1[10], s2[10];
s1 = s2;                     /* ✗ 同理 */
s1 = "hello";                /* ✗ 同理 */
```

**改法**：

```c
/* 普通数组：逐个元素复制 */
for (int i = 0; i < 3; i++) b[i] = a[i];

/* 字符串：用 strcpy */
strcpy(s1, s2);
strcpy(s1, "hello");
```

🔸 **对比：结构体是可以整体赋值的**（第 13 课）：

```c
struct Student x, y;
y = x;                       /* ✓ 这个可以 */
```

# B. 编译错误 · 语法类

## 6. `expected identifier or '('`

**通常是结构体定义末尾漏了分号**，或者函数定义写坏了。

```c
struct A {
    int x;
}                            /* ✗ 漏分号 */
struct B {
    int y;
};
```

**报错位置会很奇怪**（可能指向下一个结构体的名字），因为编译器以为你在 `}` 后面还要声明变量。

**看到这个错，先检查上一个结构体/语句块的末尾有没有分号。**

---

## 7. `expected expression`

**几种常见原因**：

```c
/* ① 把 else if 写成了别的语言的写法（第 4 课） */
if (a) { }
elif (b) { }                 /* ✗ C 里写 else if */
else if (b) { }              /* ✓ */

/* ② 用了 and / or / not（第 4 课） */
if (a and b) { }             /* ✗ */
if (a && b) { }              /* ✓ */

/* ③ switch 的 case 写错了 */
switch (n) {
case 1.5:                    /* ✗ case 后面必须是整数常量 */
case n:                      /* ✗ 不能是变量 */
case 1:                      /* ✓ */
}
```

---

## 8. `too few arguments to function call` / `too many arguments`

**意思**：函数调用时传的参数个数不对。

```c
int add(int a, int b) { return a + b; }
add(1);                      /* ✗ 少了一个 */
add(1, 2, 3);                /* ✗ 多了一个 */
add(1, 2);                   /* ✓ */
```

**改法**：看函数定义，数一数需要几个参数。

---

## 9. `use of undeclared identifier 'main'` / `linker command failed`

**意思**：找不到 `main` 函数，或者程序里有别的链接问题。

```c
int mian(void) { }           /* ✗ 拼错了！main 不是 mian */
int main(void) { }           /* ✓ */
```

**其他可能**：函数只声明了没定义（写了个 `int f(void);` 但忘了写函数体）。

---

## 10. `expected ')'` / `expected '}'` / `expected ']'`

**括号不配对。**

```c
if (a > 0 {                  /* ✗ 少了 ) */
for (int i = 0; i < n; i++ { }  /* ✗ 少了 ) */
int a[5;                     /* ✗ 少了 ] */
```

**改法**：CLion 里把光标放在括号上，它会高亮配对的另一个括号。**从报错行往前找最近的未闭合括号。**

---

## 11. `'/*' within block comment`

**意思**：注释里面又出现了 `/*`。

```c
/*
 *  说明文字
 *  /* 这是内层注释 */      ← ✗ 会提前结束外层注释
 */
```

**C 的块注释不能嵌套。** 内层的 `*/` 会终止外层注释，导致后面一大段文字被当成代码。

**改法**：把内层的注释符号换成别的写法，比如用引号或者括号：

```c
/*
 *  说明文字
 *  （这是内层说明，不要写 /* */ ）
 */
```

或者干脆用 `//` 行注释。

---

## 12. `implicit declaration of function`（老编译器 / `-Wimplicit-function-declaration`）

同第 4 条，漏 `#include` 或漏函数声明。**在 macOS 上会直接变成错误。**

---

## 13. `conflicting types for 'xxx'`

**意思**：同一个函数（或变量）被声明成了两个不同的类型。

```c
int f(int a);
double f(int a);             /* ✗ 前面说是 int，这里说是 double */
```

**常见于**：函数声明和定义的返回值类型不一致。

```c
int add(int a, int b);       /* 声明：返回 int */
double add(int a, int b) { } /* ✗ 定义：返回 double */
```

---

## 14. `control reaches end of non-void function`（警告）

**意思**：有返回值的函数，某条路径上没有 `return`。

```c
int check(int n) {
    if (n > 0) return 1;
    /* ✗ n <= 0 时没有 return，会返回垃圾值 */
}

int check(int n) {
    if (n > 0) return 1;
    return 0;                /* ✓ 所有路径都有返回 */
}
```

⚠️ **这个警告必须改。** 它不是"可选提示"，是真 bug——程序返回的会是一堆垃圾数据。

---

# C. 编译错误 · 类型类

## 15. `incompatible integer to pointer conversion` / `incompatible pointer types`

**意思**：指针和普通变量/不同类型指针搞混了。

```c
int x = 5;
int *p = x;                  /* ✗ x 是 int，p 要地址 */
int *p = &x;                 /* ✓ */

void set(int *a);
int n;
set(n);                      /* ✗ 应该传地址 */
set(&n);                     /* ✓ */
```

**好消息**：这类错是**编译错误**，不会悄悄出错。编译器还会提示 `did you mean to use '&'?`。

---

## 16. `member reference type 'X *' is a pointer; did you mean to use '->'?`

**意思**：你手上是结构体指针，却用了 `.`。

```c
struct Student s;
struct Student *p = &s;

p.id                         /* ✗ 指针要用 -> */
p->id                        /* ✓ */
s->id                        /* ✗ 变量要用 . */
s.id                         /* ✓ */
```

🔸 **规则：变量用 `.`，指针用 `->`。** 编译器会明确告诉你该用哪个，照着改就行。

---

## 17. `format specifies type 'int' but the argument has type 'double'`（警告）

**意思**：格式符和参数类型不匹配。

```c
double d = 3.5;
printf("%d\n", d);           /* ✗ double 不能用 %d */
printf("%f\n", d);           /* ✓ */

int n = 10;
printf("%f\n", n);           /* ✗ int 不能用 %f */

double x;
scanf("%f", &x);             /* ✗ scanf 里 double 必须用 %lf */
scanf("%lf", &x);            /* ✓ */
```

⚠️ **`printf` 不检查格式符**（因为参数是运行时传的），所以这类问题**通常只是警告甚至不报**，运行时输出垃圾值。

**格式符速查**：

| 类型 | printf | scanf |
|---|---|---|
| `int` | `%d` | `%d` |
| `long` | `%ld` | `%ld` |
| `float` | `%f` | `%f` |
| `double` | `%f` | **`%lf`** |
| `char` | `%c` | `%c` |
| 字符串 | `%s` | `%s` |
| `sizeof` 结果 | `%zu` | — |

---

## 18. `array has incomplete element type 'int[]'`

**意思**：二维数组传参时**没写列数**。

```c
void f(int a[][])           /* ✗ 列数必须写 */
void f(int a[][4])          /* ✓ */
void f(int a[3][4])         /* ✓ 行数也写了，但会被忽略 */
```

**原因**（第 11 课）：编译器算 `a[i][j]` 的地址时需要知道一行有多长。

---

## 19. `variable-sized object may not be initialized`

**意思**：用变量当数组长度，还想初始化。

```c
int n = 5;
int a[n] = {0};              /* ✗ 长度是变量时不能这样初始化 */
int a[5] = {0};              /* ✓ */
```

**改法**：用宏定义长度，或者声明个大一点的固定数组。

```c
#define MAXN 100
int a[MAXN] = {0};
```

---

## 20. `initializer-string for char array is too long`

**意思**：字符数组装不下字符串（忘了给 `\0` 留位置）。

```c
char s[5] = "hello";         /* ✗ 5 个字符 + \0 = 需要 6 格 */
char s[6] = "hello";         /* ✓ */
char s[] = "hello";          /* ✓ 让编译器自己数，最省事 */
```

---

# D. 运行时的怪现象

## 21. `Segmentation fault: 11` / `zsh: segmentation fault`

**意思**：程序访问了不属于它的内存。**这是最常见的运行时崩溃。**

**六个常见原因**：

| 原因 | 例子 | 怎么找 |
|---|---|---|
| **数组越界写** | `int a[5]; a[10] = 1;` | 检查所有循环的边界，尤其是 `<=` |
| **指针没初始化就解引用** | `int *p; *p = 5;` | 检查指针声明后有没有赋值 |
| **`scanf` 忘了 `&`** | `scanf("%d", n);` | 逐个检查 `scanf` |
| **递归没有出口** | `int f(int n){return f(n-1);}` | 检查递归的终止条件 |
| **链表节点的 `next` 没置 `NULL`** | `malloc` 后忘了 `p->next = NULL` | 检查每个新节点 |
| **`fopen` 返回 `NULL` 就用** | 文件不存在时 | 检查 `if (fp == NULL)` |

**排查方法（从易到难）**：

1. 先看**有没有数组**，把循环条件里的 `<=` 全改成 `<` 试试
2. 再看**有没有 `scanf`**，检查 `&`
3. 再编译时**加上 `-g` 参数**，用调试器定位
4. 用"二分法"：把程序后半段注释掉，看还崩不崩，逐步缩小范围
5. 最土但有效：在怀疑的地方插 `printf("到这里了\n");`，看崩在哪一句之前

## 22. 程序卡住不动（死循环）

**意思**：循环的退出条件永远不成立。

```c
/* ① while 忘了步进 */
int i = 0;
while (i < 5) {
    printf("%d\n", i);       /* ✗ 忘了 i++ */
}

/* ② for 的步进方向反了 */
for (int i = 0; i < 5; i--) { }   /* ✗ i 越来越小 */

/* ③ 条件用了永远为真的东西 */
while (n) { }                /* n 是 1 时永远循环 */

/* ④ 迭代法没更新变量（第 6 课） */
while (fabs(nx - x) >= 1e-6) {
    nx = x - f/df;
    /* ✗ 忘了 x = nx; → 差值永远不变 */
}
```

**排查方法**：在循环里插一句 `printf("i=%d\n", i);`，看 `i` 有没有在变、往哪个方向变。

**如果是循环本来就该跑很久**（比如穷举 90 万个数），耐心等或者优化算法。但**嵌套太深的穷举**（比如 5 层循环）确实会很慢。

## 23. 输出一堆莫名其妙的数字 / 乱码

**五个常见原因**：

```c
/* ① 变量没初始化（第 2 课） */
int sum;                     /* ✗ 值是内存里的垃圾 */
sum = sum + 1;               /* 结果不可预测 */
int sum = 0;                 /* ✓ */

/* ② 格式符和类型不匹配（第 2、3 课） */
double x = 3.5;
printf("%d\n", x);           /* ✗ 输出一个奇怪的整数 */

/* ③ 数组越界读 */
int a[5];
printf("%d\n", a[10]);       /* ✗ 读到别的内存 */

/* ④ 字符串没补 '\0'（第 12 课） */
char s[10];
s[0] = 'h'; s[1] = 'i';
printf("%s\n", s);           /* ✗ 一直往后读到垃圾 */
s[2] = '\0';                 /* ✓ */

/* ⑤ 用了 fabs 之外的 abs 处理浮点（第 6 课） */
while (abs(nx - x) >= 1e-6)  /* ✗ abs 会把小数截断成整数 */
while (fabs(nx - x) >= 1e-6) /* ✓ */
```

**注意 ① 的隐蔽性**：局部变量不初始化时，值是**内存里上次留下的数据**。这意味着：

- 换个编译器、改个地方，结果就变了
- **有时能跑对，有时不对**——这种"时对时错"的 bug 最难查

🔸 **铁律：定义变量时顺手给个初值。** `int sum = 0;` 打几个字符的成本，比查半小时 bug 划算。

---

## 24. 结果时对时错 / 换个地方就错

**这通常意味着有"内存问题"。** 按可能性排序：

| 原因 | 检查方法 |
|---|---|
| 数组越界 | 看所有循环边界，`<=` 改 `<` |
| 变量没初始化 | 每个声明都加 `= 0` |
| 返回了局部变量的地址（第 9 课） | 搜 `return &`，看指向的是不是 `static`/全局 |
| `malloc` 后没初始化 `next` | 检查每个 `p->next = NULL` |
| 用了已释放的内存 | 搜 `free`，看之后有没有再用那个指针 |

**这类 bug 的共同点**：依赖内存的物理布局，所以"看起来随机"。**但原因一定是确定性的**——找到就能修。

## 25. 输出全挤在一行

**忘了 `\n`。** `printf` **不会自动换行**，想要换行必须自己写 `\n`（第 1 课）。

```c
printf("第一行");
printf("第二行");            /* 输出：第一行第二行 */
printf("第一行\n");          /* ✓ */
```

---

## 26. 输入被"吃掉"了 / 读到的字符不对

**`%c` 前面必须有空格**（第 3 课）：

```c
int n;
char c;
scanf("%d", &n);
scanf("%c", &c);             /* ✗ 读到的是上一行残留的回车符 */
scanf(" %c", &c);            /* ✓ 前面的空格会跳过空白字符 */
```

**`scanf("%s")` 读不到带空格的内容**（第 12 课）：

```c
char s[100];
scanf("%s", s);              /* ✗ 输入 "hello world" 只能读到 "hello" */
fgets(s, 100, stdin);        /* ✓ 读整行 */
```

---

## 27. 除法结果不对（小数丢了）

**整数除法会砍掉小数**（第 2 课）：

```c
int a = 7, b = 2;
double r = a / b;            /* ✗ r = 3.0 */
double r = (double)a / b;    /* ✓ r = 3.5 */
double r = a / 2.0;          /* ✓ r = 3.5 */
```

**这个错误不报错，只是答案错。** 写除法时先问自己：两边是不是都是整数？

---

## 28. 浮点数判断相等失败

**浮点数不能用 `==` 比较**（第 3 课）：

```c
double a = 0.1 + 0.2;
if (a == 0.3) { }                    /* ✗ 永远不成立 */
if (fabs(a - 0.3) < 1e-6) { }        /* ✓ */
```

---

## 29. 字符串比较结果永远不对

**不能用 `==` 比较字符串**（第 12 课）：

```c
char a[] = "hello", b[] = "hello";
if (a == b) { }              /* ✗ 比较的是地址，永远不成立 */
if (strcmp(a, b) == 0) { }   /* ✓ */
```

⚠️ **这个错误不报错、不崩溃、程序正常跑，只是分支永远走错。** 用惯了"字符串可以用 `==` 比较"的语言的人特别容易犯，务必留意。

---

## 30. 生成的文件是空的 / 内容不全

**忘了 `fclose`**（第 14 课）：

```c
FILE *fp = fopen("out.txt", "w");
fprintf(fp, "%d\n", 42);
/* ✗ 没 fclose，数据可能还在缓冲区里 */
fclose(fp);                  /* ✓ */
```

**其他原因**：

- `fopen` 用了 `"r"` 模式却想写（应该用 `"w"`）
- 文件生成在了**别的目录**（CLion 的工作目录通常是 `cmake-build-debug/`）
- `fopen` 返回 `NULL` 但没检查，后面的 `fprintf` 静默失败

**找文件在哪**：在 CLion 里右键项目根目录 → Open in → Finder，然后看 `cmake-build-debug/`。或者把 `fopen` 的路径改成绝对路径。

# E. 警告也要看

**警告不是错误，程序能编译。但很多警告指向真 bug。**

## 必改的警告

| 警告 | 意思 | 为什么要改 |
|---|---|---|
| `variable 'x' is uninitialized when used here` | 用了未初始化的变量 | **值不可预测**，是真 bug |
| `non-void function does not return a value in all control paths` | 某条路径没 return | **返回垃圾值** |
| `address of stack memory associated with local variable 'n' returned` | 返回了局部变量的地址 | **悬空指针**，时对时错 |
| `using the result of an assignment as a condition without parentheses` | `if (x = 5)` 写成了赋值 | 条件恒真/恒假 |
| `format specifies type 'X' but the argument has type 'Y'` | 格式符和类型不匹配 | 输出垃圾值 |

## 可以暂不处理的警告

| 警告 | 说明 |
|---|---|
| `unused variable 'x'` | 定义了没用的变量。**骨架里预留的变量会触发，正常。** |
| `unused parameter 'ch'` | 函数参数没用。有些题目要求固定的函数签名，正常。 |
| `implicit conversion loses integer precision` | `long` 赋给 `int` 之类。小数据量下无影响。 |

🔸 **怎么让警告显示出来**：CLion 默认就开 `-Wall`。命令行编译要自己加：

```bash
clang -std=c11 -Wall -Wextra -g 程序.c -o 程序
```

# 附：修改代码后的标准检查顺序

改完一段代码、程序行为不对的时候，**按这个顺序查，能覆盖大部分问题**：

```
1. 编译有没有 error？        → 先修编译错误，看信息里的行号
2. 有没有"必改的警告"？      → 见 E 节表格
3. 数组循环边界对不对？      → <= 改 <，这个是重灾区
4. scanf 有没有漏 &？        → 逐个检查
5. 变量都初始化了吗？        → 局部变量不初始化就是垃圾值
6. 格式符和类型匹配吗？      → %d / %f / %lf / %ld
7. 除法的两边都是整数吗？    → 想要小数就写 2.0
8. 字符串比大小用 strcmp 了吗？
9. 文件操作有没有 fopen 检查 + fclose？
10. 实在找不到 → 插 printf 定位
```

**第 10 条永远有效。** 在怀疑的地方插 `printf`，看程序到底走到哪一步、变量的值是多少。这是最土也最可靠的办法，不要嫌它低级。

## 最后的建议

**遇到报错不要慌。** C 的报错看起来吓人，但：

- **编译错误**：编译器已经把行号告诉你了，只是需要翻译一下英文
- **运行时错误**：一类是崩溃（八成是越界或空指针），一类是结果不对（八成是没初始化或类型问题）

**翻这份手册翻三次，你就会发现报错信息自己看得懂了。** 到那时这份手册就不需要了。
