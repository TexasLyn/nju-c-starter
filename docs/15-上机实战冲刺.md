## 1. 上机题长什么样

国内高校的 C 语言上机题结构大同小异：

| 大题 | 分值 | 内容 |
|---|---|---|
| 一、改错题 | **约 20 分** | 给你一段完整程序，里面埋了 3~5 处错误，让你改对 |
| 二、编程题 | **约 20 分** | 从零写一个程序（通常要求写文件） |
| **合计** | **约 40 分** | 90 分钟 |

（分值各校不同，但**题型和套路基本一致**——这正是这一课值得认真过一遍的原因。）

### ⚠️ 两个硬性要求（不知道会直接丢分）

**① 程序文件名必须是 `solution.c`**（有时是 `solution2.c`）

**② 结果必须写入指定文件**：最常见的是 **`result.txt`**，也可能是 `output.txt`

**这意味着：每道编程题的最后，你都必须有一段写文件的代码。** 忘了写文件 = 那道题基本没分，不管你算得对不对。

## 2. 改错题的规则（务必先搞清楚）

改错题通常还有一条特别的评分规则：

> 可以修改语句的部分内容、可以调整语句顺序、可以少量增加声明和预处理命令，
> **但不能增加语句，也不能删除语句。**

🔸 **这一条决定了你的改错策略**：

| 允许 | 不允许 |
|---|---|
| 改一个符号（`=` → `==`） | 加一行 `scanf(...)` |
| 改循环条件（`<` → `<=`） | 删掉一行 |
| 加 `&` 或 `*` | 加一个 `if` 块 |
| 加 `#include <string.h>` | 加变量声明之外的新语句 |
| 调整几行的顺序 | — |

**所以：改错题的答案往往是"改几个字符"，不是"重写一段逻辑"。** 如果你发现要加一整行新代码才能修好，八成是思路错了——再找找是不是某一行只需要改个符号。

## 3. 改错题的常见错误类型（按频率排序）

**记住这张表，扫描时按顺序过一遍，命中率很高。**

### ① 漏 `&` 或多 `&`（最高频）

```c
scanf("%d", x);              /* ✗ 漏了 & */
scanf("%d", &x);             /* ✓ */

scanf("%d", &n);             /* ✓ */
scanf("%s", &s);             /* ✗ 数组名前面不加 & （虽然常常能跑） */
```

### ② 分号、括号、花括号问题

```c
int a = 5               /* ✗ 漏分号 */
if (a > 0)              /* ✓ */
for (i = 0; i < n; i++) /* ✓ 三个部分都有分号 */
```

### ③ 循环边界差 1

```c
for (int i = 0; i <= n; i++)     /* ✗ 越界，应该是 < n */
for (int i = 1; i < n; i++)      /* ⚠️ 看题意：想遍历 1..n 就是 <= n */
```

### ④ `=` 和 `==` 混用

```c
if (x = 0) { }              /* ✗ 赋值，条件恒假 */
if (x == 0) { }             /* ✓ */
```

### ⑤ 类型不匹配

```c
double x;
scanf("%f", &x);            /* ✗ double 要用 %lf */
printf("%d\n", x);          /* ✗ double 不能用 %d */
printf("%f\n", x);          /* ✓ */
```

### ⑥ 指针相关的错

```c
int *p = &x;
printf("%d\n", p);          /* ✗ 打印的是地址，应该是 *p */
*p = 10;                    /* ✓ */
a = 10;                     /* ✗ a 是 int*，改的是指针本身，应写 *a = 10 */
```

### ⑦ 数组和字符串

```c
int a[5];
for (int i = 0; i <= 5; i++) a[i] = 0;    /* ✗ 越界 */

char s[5] = "hello";                       /* ✗ 装不下 \0 */
if (s1 == s2)                              /* ✗ 比较字符串要用 strcmp */
strcpy(s, "abc");                          /* ✓ 不能用 s = "abc" */
```

### ⑧ 函数相关

```c
void f(void) { return 1; }                 /* ✗ void 不能有返回值 */
int f(int a, b) { }                        /* ✗ b 缺类型 */
int f(void) { if (x) return 1; }           /* ✗ 不是所有路径都有 return */
/* 函数调用写在定义之前却没声明 */          /* ✗ 需要声明或调整顺序 */
```

### ⑨ 缺 `#include`

```c
/* 用了 sqrt 却没 #include <math.h> */      /* ✗ */
/* 用了 strcmp 却没 #include <string.h> */  /* ✗ */
/* 用了 malloc 却没 #include <stdlib.h> */  /* ✗ */
```

🔸 **扫描顺序建议**：先看 `scanf` 有没有漏 `&`，再看所有 `for` 的边界，再看 `if` 里的 `=`，最后扫一遍分号括号。这四类覆盖了大部分。

## 5. 编程题的固定套路（背下来）

**每一道编程题都按这五步写，不要临场发挥。**

```c
#include <stdio.h>
#include <stdlib.h>          /* malloc 需要 */
#include <string.h>          /* 字符串函数需要 */
#include <math.h>            /* 数学函数需要 */

/* ① 如果有需要，写辅助函数（素数判断、排序、reverse 等） */

int main(void)
{
    /* ② 读入数据（从键盘或从 input.txt） */

    /* ③ 计算结果 */

    /* ④ 写文件 —— 【这一步是上机题要求，绝对不能忘】 */
    FILE *fp = fopen("result.txt", "w");
    if (fp == NULL) {
        return 1;
    }
    /* fprintf(fp, ...) 按题目要求的格式写 */
    fclose(fp);

    /* ⑤ 同时打印到屏幕（方便自己确认，不影响评分） */
    printf(...);

    return 0;
}
```

🔸 **第 ④ 步是死记硬背的模板**。动手前先把这段写下来，再填中间的算法，就不会忘。

### 关于文件名的应变

题目说写哪个文件就写哪个。**看到这些名字要能立刻反应过来**：

| 文件名 | 用途 |
|---|---|
| `input.txt` / `in.txt` | 输入数据（有的题目要你读） |
| `result.txt` / `output.txt` | 结果文件 |
| `solution.c` / `myf.c` | 你的程序该叫什么名字（**是文件名规定，不是文件操作**） |

⚠️ **注意区分**：左边那一列是**你交上去的源文件名**，中间那列是**你的程序运行时生成的结果文件**。两者完全不是一回事——**题目要哪个就写哪个，名字一个字都不能差。**

## 6. 常见的上机编程题（了解难度）

下面几道是上机题里反复出现的类型，可以感受一下难度：

**题 A：反序素数**
> 写函数 `int rev_prime(int m, int n, int x[])`，求 [m, n] 内所有"反序素数"存入 x，返回个数。用 `fprintf` 把结果写入文件。

（这就是 `practice/L14_1.c`，你已经练过了。）

**题 B：找最后一个素数 + 局部排序**
> 在数组中找最后一个素数，对它之前的部分做局部选择排序，结果写入文件。

**题 C：矩阵反对角线**
> 5×5 矩阵，把每行的和填入反对角线，再排序。

**题 D：字符串数组重排**
> 把字符串数组里最短的移到最前、最长的移到最后。

**题 E：子序列转折点**
> 找递增/递减子序列的转换元素下标，结果写入 `output.txt`。

🔸 **观察共同点**：每道题都是**你在前 14 课练过的几个小操作的组合**。

| 模拟题 | 用到前面的哪些课 |
|---|---|
| 反序素数 | L07（函数）+ L02（拆数字）+ L14（写文件） |
| 最后一个素数 + 局部排序 | L05（素数）+ L11（排序）+ L14（写文件） |
| 矩阵反对角线 | L11（二维数组）+ L05（求和） |
| 字符串数组重排 | L12（字符串）+ L10（数组操作） |
| 子序列转折点 | L05（循环比较）+ L14（写文件） |

**所以上机练习不是考新知识，是考"你能不能把学过的东西组合起来"。** 前 14 课认真做过，这里就是水到渠成。

## 8. 上机题时间分配建议

90 分钟，40 分：

| 时间 | 做什么 |
|---|---|
| 0-5 分钟 | 把三道题都读一遍，判断哪道最有把握 |
| 5-40 分钟 | 改错题（20 分，性价比最高，先拿下） |
| 40-85 分钟 | 两道编程题（先做有把握的，别忘了写文件） |
| 85-90 分钟 | 检查：文件名对不对？`fclose` 有没有？两题的文件都生成了吗？ |

🔸 **改错题值得先做**：20 分，而且是"能编译通过的程序里找错"，比从零写程序容易。

### 交卷前的检查清单

1. **程序文件名**是 `solution.c` 吗？
2. **两道编程题都写文件了吗？** 文件名对不对（`result.txt`？）
3. **`fclose` 都写了吗？**
4. **输出的格式**和题目要求一致吗（空格、换行、保留几位小数）？
5. 编译**没有 error** 吗？（有 warning 没关系，有 error 就没分）

## 9. 本模块最少必要记忆

1. **上机练习 40 分 = 改错 20 + 编程 20**，程序名 `solution.c`，结果写 `result.txt`
2. **改错题只能改字符，不能增删语句**
3. **改错扫描顺序**：`scanf` 的 `&` → `for` 边界 → `=` 和 `==` → 分号括号
4. **编程题五步模板**：include → 读入 → 计算 → **写文件** → 打印
5. **`fopen` 后检查 NULL，`fclose` 不能忘**
