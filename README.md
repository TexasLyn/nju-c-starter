# C 语言自学教材 · nju-c-starter

> 一套**能自学完**的 C 语言教程：15 课讲义 + 75 道练习 + 参考答案 + 一键评测脚本 + 可运行的 CMake 工程。
> 从「完全没写过代码」到「能独立写出上机题」，全部在这里。

---

## 这是什么

一套完整的 C 语言自学包。**没有前置要求**——如果你已经会别的编程语言，有一条[快路](docs/A-有编程基础怎么快速过.md)帮你省掉 1/3 的时间。

| | |
|---|---|
| **15 课讲义** | 每课 30~40 分钟读完，结尾有「最少必要记忆」和「新手最常犯的 3 个错」 |
| **75 道练习** | 每题都有骨架（题目写在文件开头）+ 参考答案 + 测试数据 |
| **一键评测** | 像在线判题系统一样：编译你的代码 → 喂输入 → 和标准答案比对 → 指出哪一行不一样 |
| **四种入门路径** | 零安装在线编译器 / Windows / macOS / 让 AI 帮你装 |
| **AI 提示词** | 5 个写好的提示词，让你的 AI 助手知道「引导而不是直接给答案」 |

**课程范围**：从「第一个 C 程序」到「文件读写」，覆盖指针、数组、字符串、结构体、链表这一整条主线，最后有一个**上机实战模块**（改错题 + 编程题的固定套路）。

## 怎么运行和评测

### 一键评测（推荐）

```bash
python3 tests/check.py L01        # 跑 L01 开头的所有题
python3 tests/check.py L01_1      # 只跑一道题
python3 tests/check.py L14 --dir answers   # 看参考答案的输出
python3 tests/check.py --compile-only      # 只检查能不能编译
```

评测脚本会：**编译你的代码 → 自动喂入测试数据 → 和标准答案逐行比对 → 告诉你哪一行不一样**。

### 不想用脚本

```bash
# macOS / Linux
clang -std=c11 -Wall -Wextra -g practice/L01_1.c -o /tmp/a && /tmp/a

# Windows PowerShell
gcc -std=c11 -Wall -Wextra -g practice\L01_1.c -o L01_1.exe; .\L01_1.exe
```

⚠️ **`-Wall -Wextra` 一定要加**，很多 bug 靠警告才能发现。

### 用 CLion（可选，最舒服）

用 CLion 打开这个目录，它会自动把 `practice/` 和 `answers/` 里每个 `.c` 文件识别成一个**可单独运行的目标**——右上角下拉框选题目名（比如 `L01_1`），点绿色三角就跑。

新加文件后点一下顶部的「Reload CMake Project」刷新。

## 三件必须知道的事

### ① 指针是螺旋式教学的

指针在 C 里最难，所以这套材料**刻意不一次性讲透**：

| 课 | 讲什么 |
|---|---|
| 03 | 先让你记住「`scanf` 要写 `&`」，**不解释为什么** |
| 08 | 讲清「地址」是什么，`&` 和 `*` 怎么用 |
| 09 | 用 `static` 变量解释「悬空指针」 |
| 12 | 用字符串把它落实（`s[i]` 就是 `*(s+i)`） |
| 13 | 用链表收口（指针真正发挥威力的地方） |

**在第 08 课之前遇到 `&`，照抄就行，不要停下来死磕。** 到 08 课你会恍然大悟。

### ② 教材代码可能在现代环境上编译不过

很多教材和学校的参考答案里用 `gets()` 和 `conio.h` / `clrscr()`。这两样在 macOS 上**不存在**，在 Windows 的新编译器上也基本不可用。

| 教材写法 | 本机替换 |
|---|---|
| `#include <conio.h>` | 删掉这一行 |
| `clrscr();` | 删掉这一句 |
| `gets(str);` | `fgets(str, sizeof(str), stdin);` + 去掉换行 |

讲义里两种写法都会给。**自己练习用现代写法，如果课程要求按教材写法交就按课程要求来。**

### ③ 大部分概念第一遍看就是会不懂，这是正常的

C 的设计一层套一层，后面的概念需要前面的做地基。「地址」「指针」在第 1 课讲不清楚，因为你还不知道变量在内存里长什么样。

所以讲义里遇到这种地方会明确标注：

> 🔸 **这里先记住写法就行，第 N 课会回来解释。**

**看到这种标记，照抄写法继续往下走。** 别停在那儿死磕，那是效率最低的学法。

反过来，讲义里标了 **⚠️** 和「关键」的地方，请务必想清楚——那些是地基。

## 环境要求

| 需要什么 | 为什么 | 能不装吗 |
|---|---|---|
| C 编译器（clang 或 gcc） | 编译你的代码 | **不能**，这是 C 语言的前提 |
| Python 3 | 跑 `tests/check.py` | 能，手动对答案也行 |
| CLion | 图形界面一键运行 | 能，命令行完全够用 |

最省事的组合：**MinGW（Windows）/ 命令行工具（macOS）+ Python 3 + 任意编辑器**。

## 遇到问题怎么办

1. **先查 [报错速查手册](docs/99-报错速查.md)** —— 30 种常见报错都有中文解释
2. **分清是哪种错**：
   - 编译报错 → 语法问题，按报错行号改（**注意：报错行号常常指在下一行**）
   - 跑起来但结果不对 → 逻辑问题，用 `printf` 插桩调试
   - 卡住不动 → 死循环，检查循环的退出条件
   - 崩溃（Segmentation fault）→ 九成是数组越界或空指针
3. **自己写不出来再看答案**，顺序很重要
4. **`printf` 调试永远有效**，别嫌它土
5. **有 AI 的话** → 用 [prompts/01-助教模式.md](prompts/01-助教模式.md)，比问"这题怎么做"有用得多
